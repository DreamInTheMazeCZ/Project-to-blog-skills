# 비공개 작업 공간 문서 템플릿

아래 문서는 전부 **내부 분석용**이다. 실제 비밀값·개인정보·고객 원문은 보존하지 않는다. 필요한 항목만 작성하고 미확인 항목은 표시한다.

## 디렉터리

```text
<output>/<project-slug>/
  PROJECT_ANALYSIS.md
  EVIDENCE_MAP.md
  DECISIONS.md
  SERIES_PLAN.md
  PUBLICATION_REVIEW.md
  drafts/
    01-<topic>.md
    02-<topic>.md
```

## PROJECT_ANALYSIS.md

```markdown
# [프로젝트명] 분석
- 원본 경로 / Git HEAD / 분석일 / 이력의 한계:
- 목적 / 주요 사용자 / 해결 과제:
- 유형(복수 선택) / 각 유형의 이유:
- 현재 구현된 핵심 기능:
- 엔드투엔드 흐름 / 핵심 모듈 경로:
- 코드와 문서의 불일치:
- 확인된 결과와 평가 환경:
- 구현 사실과 구분해야 할 계획:
- 기술적 설명 가치가 있는 주제:
- 미확정 사항(Q-ID 연결):
```

## EVIDENCE_MAP.md

```markdown
| ID | 주장 / 주제 | 근거 종류 | 정확한 출처(경로/라인 또는 커밋) | 등급(A/B/U/C) | 공개 처리 |
|----|-------------|-----------|----------------------------------|----------------|-----------|
| E-001 | ... | 코드 | src/...:10-25 | A | 사용 |
| E-002 | ... | 사용자 진술 | Q-01 답변 | U | 동기로만 사용 |
```

출처는 가능하면 파일 경로·함수·라인·커밋 해시를 기록하고, 지표는 원자료 및 측정 조건까지 기록한다. 줄번호가 바뀔 수 있으므로 함수명·기준 Git SHA를 함께 남기면 좋다.


## PUBLICATION_REVIEW.md

```markdown
# 외부 공개 전 검토
- 공개 허용 범위 / 사용자 결정 ID:
- 공개에서 제외한 주제(민감값 기록 금지):
- 사실 확인이 필요한 주장 ID:
- 미해결 P0/P1 질문:
- 각 글의 사실·기밀·문체·중복·SEO 점검 상태:
- 공개 전 사용자에게 확인할 사항:
- 상태: 내부 초안 / 게시 승인 전
```

## drafts/*.md

기존 Mazora 콘텐츠 스키마를 확인했다면 그 frontmatter를 따른다. 그렇지 않으면 범용 Markdown으로 작성하고 'frontmatter 미적용'을 리뷰 파일에 남긴다. 내부 evidence ID, 비공개 검토 메모, P0/P1 질문을 게시용 본문에 섞지 않는다. 게시글의 원문과 내부 검증 자료를 별도로 관리한다.
