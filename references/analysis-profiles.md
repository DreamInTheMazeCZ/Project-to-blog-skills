# 동적 프로젝트 분석 프로필

이 문서는 체크리스트이다. **고정 목차가 아니다.** 분석에 해당되는 프로필 여러 개를 사용하되 프로젝트에 존재하지 않는 기술이나 단계를 추가하지 않는다. 프로젝트의 실제 가치는 유형보다 문제 해결과 구현 근거에서 나온다.

## 공통 질문
- 누구의 어떤 문제를 해결하는가? 사용자와 워크플로는 무엇인가?
- 실제 진입점, 핵심 모듈, I/O, 상태 저장, 배포 인터페이스는 무엇인가?
- 주요 데이터 흐름, 외부 연동, 예외 흐름, 검증된 결과는 무엇인가?
- 무엇이 구현 사실이고 무엇이 문서상의 계획·미확인인가?
- 핵심 기능을 설명할 때 독자가 재사용할 수 있는 방법은 무엇인가?

## ML / 예측 / 추천
- 원천 데이터와 라벨, 분할 기준, 전처리, 누수 방지, 피처 엔지니어링
- 후보 모델, 학습·튜닝, 앙상블, 실험 재현, 검증 지표·데이터 크기·평가 기간
- 추론·서빙, 모니터링·재학습, 운영 피드백의 실제 구현 상태
- 하이퍼파라미터를 사용했다는 사실과 선택 이유는 별개의 주장
- 공개할 수 있는 지표만 검증 단위/데이터 출처와 함께 서술

## LLM / RAG / Agent
- 입력 문서/정보, 파싱·청킹·임베딩, 검색/재정렬, 프롬프트, 생성·근거 제시
- 라우팅·도구 호출, 권한/개인정보 취급, 실패·안전한 폴백, 평가/로깅 여부
- 사용 모델·벡터 저장소는 코드/설정으로 검증; 비용·응답 품질 개선은 자료가 있을 때만
- 단순 API 호출을 자율형 에이전트처럼 과장하지 않음

## AI / 업무 자동화 / 시스템 연동
- 기존 수작업 흐름, 자동화 트리거, 입력/출력, 단계별 책임 구분
- 규칙 기반과 AI 기반 처리의 경계, 사람의 승인 지점, 예외·복구·재시도
- 스케줄러/워크플로, 외부 ERP/CRM/내부 시스템 연동의 실제 범위
- '완전 자동화', '업무시간 절감'은 검증 근거와 수동 단계가 확인될 때만 사용

## 데이터 엔지니어링 / ETL
- 데이터 원천과 스키마, 수집/변환/검증/적재, 멱등성, 중복/결측/정합성
- 배치/실시간 여부, 실행 주기, 운영 실패 처리, 데이터 품질 지표
- 백필/이관/스키마 변경 등 확인 가능한 실행 흐름

## Web / SaaS / 앱
- 핵심 사용자 시나리오, 프론트/백 구조, 상태 관리, API·인증·권한
- 저장·캐시·성능, 배포·모니터링, UX와 접근성 설계의 실제 구현
- 인가/보안 우회, 임시 환경설정 등은 공개하지 않으며 보안성 인증 주장 금지

## Vision / OCR / 영상 처리
- 입력 영상/이미지 조건, 탐지·인식·트래킹·후처리 파이프라인
- 카메라/설비 연동, 정확도/지연 측정, 장애 및 사람 검증 루프
- 환경 제약(화각/조명/화질)과 실제 검증 범위를 혼동하지 않음

## 혼합형 예시
`OCR → ETL → LLM 분류 → API → 승인 UI`이면 한 범주를 강제하지 않고 기능 가치를 기준으로 묶는다. 독립적으로 설명 가능한 처리 단계만 별도 글로 분리한다.
